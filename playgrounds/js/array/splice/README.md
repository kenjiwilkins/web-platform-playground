## 試したこと

`main.js` の 9 ケースを、Node（V8）で同じコードを実行して確かめた。元の配列は毎回 `['a', 'b', 'c', 'd', 'e']`。
ブラウザ（sandbox）での描画は、この環境では確認できていない。

| 呼び出し                 | 戻り値          | 呼び出し後の配列                |
| ------------------------ | --------------- | ------------------------------- |
| `splice(1, 2)`           | `["b","c"]`     | `["a","d","e"]`                 |
| `splice(1, 0, "x", "y")` | `[]`            | `["a","x","y","b","c","d","e"]` |
| `splice(1, 2, "X")`      | `["b","c"]`     | `["a","X","d","e"]`             |
| `splice(-2, 1)`          | `["d"]`         | `["a","b","c","e"]`             |
| `splice(2)`              | `["c","d","e"]` | `["a","b"]`                     |
| `splice(2, undefined)`   | `[]`            | 変化なし                        |
| `splice()`               | `[]`            | 変化なし                        |
| `splice(10, 1, "z")`     | `[]`            | 末尾に `"z"` が追加された       |
| `splice(3, 99)`          | `["d","e"]`     | `["a","b","c"]`                 |

- **戻り値は「取り除いた要素」で、配列自体は書き換わる。** 挿入だけのとき（`deleteCount` が 0）は、戻り値が空配列になる。
- **負の開始位置は末尾から数える。** `-2` は後ろから 2 番目。

## ハマりどころ

- **`splice(2)` と `splice(2, undefined)` は別物。** 前者は末尾まで削除したが、後者は何も削除しなかった。
  `deleteCount` に `undefined` を明示すると、「省略」ではなく 0 として扱われる。変数経由で渡すときに起きやすい。
- **範囲外の開始位置は、末尾に追加になる。** `splice(10, 1, "z")` は何も削除せず、`"z"` が末尾に入った（エラーにはならない）。
- **元の配列が変わるので、共有している配列には注意が要る。** 元を残したいときは、非破壊版の `toSpliced()` がある（Node では `typeof Array.prototype.toSpliced` が `function` だった）。
  `toSpliced()` の挙動そのものは、この Playground では試していない。

## バリアント `pagination`: ページネーション

23 件のタスクを、1 ページ 3 / 5 / 10 件で表示する一覧。`splice()` を 3 か所で使う。

- **ページの切り出し:** `items.slice().splice((page - 1) * size, size)`。コピーに対して呼ぶので、元の配列は変わらない。
- **削除:** `items.splice(i, 1)`。ページ数が減ったときは、現在のページを範囲内に補正する。
- **追加:** `items.splice(at, 0, item)`。表示中ページの先頭に挿入する。

Chrome 156 で、ページ送り・削除・追加・件数の変更を実際に操作して確かめた
（組み合わせた HTML を別のローカルサーバーで開いた。このアプリの sandbox 経由ではない）:

- 5 件 / ページでは、1 ページ目のページ番号が `1 2 … 5`、3 ページ目が `1 2 3 … 5`、最後の 5 ページ目が `1 … 4 5` になった。
- 最終ページ（21〜23 件目）の先頭を削除すると、22 件中 21–22 件になった。追加すると、先頭に「タスク 24」が入って 23 件中 21–23 件になった。
- 10 件 / ページの 3 ページ目（最終）で 3 件削除すると、20 件・2 ページになり、現在のページが 3 から 2 に補正された。

### アクセシビリティの注意

- **削除したボタンは消えるので、フォーカスが `body` に落ちる。** 確認したところ、削除ボタンを押すと `document.activeElement` が `BODY` になった。
  キーボードで操作している人は、削除のたびに先頭からやり直しになる。このデモでは削除後に一覧（`tabindex="-1"`）へフォーカスを移して対処している。
  移したあとの `document.activeElement` が一覧になることを確かめた。
- ページ番号のボタンには `aria-label`（「3 ページ」）と、現在ページの `aria-current="page"` を付けている。件数の表示は `aria-live="polite"` にしている。
- 色だけで現在のページを示さないよう、現在のページは太字にしている。
- 未確認: VoiceOver での読み上げ（`aria-live` の内容、削除後に一覧へ移ったときの読まれ方）、Tab 操作の実際の移動順、色のコントラスト比。
