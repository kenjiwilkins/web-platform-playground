## 試したこと

- `showModal()` で開いて、`<form method="dialog">` のボタンや Esc で閉じる（`basic`）。
- `showModal()` と `show()` の、フォーカスと Esc の違い（`focus`。下の「アクセシビリティの注意」に結果を書いた）。
- `<form method="dialog">` で閉じたときの `returnValue`。

## アクセシビリティの注意

`focus` バリアントで、フォーカスの動きを測った（自動実行と、ボタンと Esc キーでの手操作）。

| 操作                         | `showModal()`                                               | `show()`                                                       |
| ---------------------------- | ----------------------------------------------------------- | -------------------------------------------------------------- |
| 開いた直後のフォーカス       | ダイアログ内の最初のボタン（OK）                            | 同じく OK                                                      |
| `:modal` に一致              | する                                                        | しない                                                         |
| 背景の入力欄を `focus()`     | **フォーカスできなかった**（OK のまま）                     | フォーカスできた                                               |
| `close()` のあとのフォーカス | **開いたボタンに戻った**                                    | 背景の入力欄に残った（開いたボタンには戻らなかった）           |
| Esc キー                     | `cancel` → `close` が届いて閉じ、フォーカスは開いたボタンへ | **何も起きず、閉じなかった**（`cancel` も `close` も届かない） |

- `showModal()` は、背景を操作できなくして、閉じたら元のボタンへフォーカスを戻してくれる。モーダルにしたいなら `show()` ではなく `showModal()` を使う。
- `show()` で開いたダイアログは、**Esc では閉じない**。キーボードだけの人が閉じられるように、ダイアログの中に閉じるボタンを置く必要がある。
- `show()` で閉じたあとのフォーカスは、そのときフォーカスのあった場所に残る。開いたボタンへ戻したいなら自分で `focus()` する
  （この測定では、閉じる前にフォーカスを背景の入力欄へ移していた。ダイアログ内にフォーカスがある状態で閉じた場合は試していない）。
- `basic` の `<dialog>` には、名前（`aria-label` / `aria-labelledby`）を付けていない。実際に使うときは、何のダイアログか分かる名前が要る（一般的な指針で、この Playground では確かめていない）。
- 未確認: Tab キーでのフォーカスの巡回、スクリーンリーダーでの読み上げ。
