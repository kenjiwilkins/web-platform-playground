## 試したこと

- **`title` の有無で見た目が変わる想定。** `<abbr title="...">` と `<abbr>`（title なし）、下線を `text-decoration` で消す／戻す例、
  JS から `el.title` を読む例を `index.html` / `main.js` に置いた。
  `getComputedStyle` の `textDecorationLine` / `textDecorationStyle` と `tabIndex` を console に出す。
- `title` を付けた `<abbr>` にマウスを乗せると、ツールチップが表示された。
- ブラウザ側の既定（`abbr[title]` に点線の下線が付く）は仕様の注記と MDN の説明に基づく。

## ハマりどころ

- `<abbr>` は専用のインターフェースを持たず、`HTMLElement` として扱われる。正式名称を取るのは `title` 属性（`el.title`）。
- `title` はマウスを乗せたときのツールチップとして出る。タッチ操作やキーボードでは見えにくい。

## アクセシビリティの注意

- **`<abbr>` は Tab キーでフォーカスできない。** 確認したところ、Tab で移動しても止まらなかった。
  キーボードだけの操作では、`title` のツールチップを出す手段がない。
- **VoiceOver は `title` を読まなかった。** 確認した範囲では、正式名称は読み上げられなかった。
  読み上げの挙動は製品や設定によって違い、他のスクリーンリーダーは未確認。`title` に正式名称を頼らない。
- 初出の箇所では、本文に正式名称を書いたうえで括弧内に略語を添える方が確実。

### 使い分け（一般的な知識。この Playground では試していない）

- **使う価値がある場合:** 中身が本当に略語のとき。`abbr` / `abbr[title]` で選べるので、共通 UI で略語だけを統一して見せたい（下線・色など）ときに使いやすい。
  略語だと分かる意味づけを残せるが、アクセシビリティを満たす手段にはならない。
- **避ける場合:** 略語ではないものを、スタイルを当てたいだけで `<abbr>` にしない。意味が嘘になるので `<span class="...">` にする。
- **説明を確実に見せたいとき:** `title` に頼らず、`<button>` で包む、ポップオーバーで説明を出すなど、キーボードでも操作できる形にする。
