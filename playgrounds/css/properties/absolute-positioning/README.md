## 試したこと

`top: 10px; left: 10px` の `position: absolute` の子を使って、4 つの場面を測った（値は `getBoundingClientRect()` など）。

1. **包含ブロック**
   - 祖先に `position: relative` があると、その枠の左上から (10, 10)px に置かれた（`offsetParent` はその祖先）。
   - `position` 指定のある祖先が無いと、枠の中ではなく**ページの左上から (10, 10)px** に置かれた（`offsetParent` は `body`）。ページの一番上に黄色の `abs` が出る。
2. **フローから外れる**
   - 段落が 2 つある枠の高さは 88px。1 つ目を `absolute` にすると 50px になり、1 つ目の分が詰まった。
   - `absolute` にした段落は、2 つ目の段落と**重なった**。
3. **`transform` した祖先**
   - `position` が `static` のままでも、`transform: translate(0)` を付けた祖先が包含ブロックになり、その枠の左上から (10, 10)px に置かれた（`offsetParent` はその祖先）。
4. **見た目の順と DOM の順**
   - A → B の順に書いたボタンを、`absolute` で B が上・A が下になるよう並べ替えた。Tab で移動すると、`[focus]` は **A → B の順**（DOM の順）だった。

## ハマりどころ

- `position: absolute` の基準は「親」ではなく、**最も近い `position` が `static` 以外の祖先**（または `transform` などで包含ブロックになる祖先）。
  親に `position: relative` を付け忘れると、意図せずページ全体が基準になる。
- 絶対配置の要素は、親の高さに数えられない。親の高さが 0 になったり、後ろの要素と重なったりする。

## アクセシビリティの注意

- **Tab の順は、見た目ではなく DOM の順。** 見た目で B が上・A が下でも、Tab は A → B の順に移動した。
  `absolute` で見た目の順を入れ替えると、キーボードのフォーカスが画面の上下・左右を行き来して、迷いやすい。順序を変えたいなら、DOM の順を変える。
- **絶対配置の要素は、他の要素と重なりうる。** `absolute` の段落が 2 つ目の段落と重なった（上のとおり）。
  文字を大きくしたり、画面を拡大したりしたときに、隠れて読めなくなるかどうかは確かめていない。
