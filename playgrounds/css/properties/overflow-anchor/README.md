## 試したこと

高さ 30px の項目を 20 件並べたスクロール枠を 2 つ用意し、どちらも `scrollTop = 150` までスクロールしておく。
その状態で、見えている範囲より **上に** 3 件（90px 分）を挿入して、黄色の項目（item 8）の位置を測った。

| 枠                      | 項目の位置（枠の上端から）    | `scrollTop`   |
| ----------------------- | ----------------------------- | ------------- |
| `overflow-anchor: auto` | 61px → 61px（動かない）       | 150 → **240** |
| `overflow-anchor: none` | 61px → **151px**（90px ずれ） | 150 → 150     |

- `auto`（既定）では、ブラウザが `scrollTop` を挿入分（90px）だけ自動で進めて、見ている項目を動かさなかった。
- `none` では `scrollTop` はそのままなので、挿入された分だけ見ていた項目が下へ押し出された。

## ハマりどころ

- スクロール位置が **先頭（`scrollTop = 0`）のときはアンカーが働かない**。先に少しスクロールしてから挿入する必要がある。
- アンカーの補正は `scrollTop` を書き換えるので、`none` との差は「項目の位置」と「`scrollTop`」の両方を見ると分かりやすい。
- 結果は挿入直後にレイアウトを強制して測った値。描画後にスクロール位置を見ても同じになるかは確認していない。
- `overflow-anchor` が使えるのはもともと Chrome / Firefox で、Safari が加わって Baseline Newly になった。
  未対応ブラウザでの挙動（この Playground の `detect` は `CSS.supports('overflow-anchor', 'none')`）は、このブラウザでは確かめていない。

## `none` にしたくなる場面

basic は「`auto` が効く」ことを見た。以下のバリアントは、逆に `none` にした方がよい場面を、実際のアプリの画面に見立てて作った。
どれもスクロール枠を並べ（`auto` と `none`）、ボタンで操作（読み込み 1.5 秒後に自動でも実行）して、結果を ✓ / ✗ で表示する。

### manual: チャットで過去のメッセージを読み込む

チャットを少し上へスクロールして、あるメッセージを読んでいる。「過去のメッセージを読み込む」で先頭に 3 件（168px 分）が足される。
実装側は「足した高さだけ `scrollTop` を増やす」自前の補正を入れている（履歴読み込みでありがちな実装）。

| 枠     | 読んでいたメッセージの位置 | `scrollTop`   |
| ------ | -------------------------- | ------------- |
| `auto` | 101 → **-67**              | 300 → **636** |
| `none` | 101 → 101                  | 300 → 468     |

- `auto` では、ブラウザの補正（+168）と自前の補正（+168）が**二重にかかり**、メッセージが 168px 上へ飛んだ。
- `none` にすると自前の補正だけが効いて、位置が保たれた。

### push-down: タイムラインで新着を見せたい

SNS のタイムラインを、先頭からほんの少し（`scrollTop = 4`）だけスクロールして見ている。「新着を取得」で先頭に 3 件（NEW）が足される。

| 枠     | 見えている新着 | `scrollTop` |
| ------ | -------------- | ----------- |
| `auto` | **0 / 3 件**   | 4 → **214** |
| `none` | 3 / 3 件       | 4 → 4       |

- `auto` は読んでいた位置を保つので、新着は画面の上に隠れた（読み逃す）。
- `none` では新着がそのまま見える。

### ad: 記事ページで広告が遅れて大きくなる

記事を読んでいる。広告枠の上端が画面の上端にぴったり合っていて、その下の黄色い段落を読んでいる。「広告を読み込む」で広告が 40px → 160px に伸びる（遅れて読み込まれた想定）。

| 枠                  | 読んでいた段落の位置 | `scrollTop`   |
| ------------------- | -------------------- | ------------- |
| `auto`              | 113 → **233**        | 167 → 167     |
| 記事全体を `none`   | 113 → **233**        | 167 → 167     |
| **広告だけ** `none` | 113 → 113            | 167 → **287** |

- 広告そのものがアンカーに選ばれると、広告の位置は保たれ、その下の本文が 120px 押し下げられた。
- 広告だけ `overflow-anchor: none` にすると、アンカーが本文側に移り、`scrollTop` が +120 されて読んでいた段落が動かなかった。
- 記事全体を `none` にすると補正が一切入らないので、`auto` と同じく本文が押し下げられた。「広告だけ」を外すのがポイント。

### animation: 記事ページでお知らせバナーが開く

記事を途中まで読んでいる。ページ先頭のお知らせバナーが、400ms かけて 0 → 150px に開く。

| 枠     | 読んでいた段落の位置 | `scroll` イベント | `scrollTop` |
| ------ | -------------------- | ----------------- | ----------- |
| `auto` | 87 → 87              | **49 回**         | 120 → 270   |
| `none` | 87 → **237**         | 0 回              | 120 → 120   |

- `auto` は、アニメーションの間ずっと `scrollTop` を補正し続けた（`scroll` イベントが 49 回）。見た目の位置は保たれるが、毎フレーム `scrollTop` が書き換わる。
- `none` では `scrollTop` に触らないので、イベントは出ず、段落はバナーの分だけ下へ押し出された。
- 「カクつく」かどうかまでは測っていない（回数と最終位置だけ確認した）。どちらが良いかは用途次第。

## 各バリアントのハマりどころ

- **ad の結果は、ブラウザ（エンジン）によって違う可能性がある。**
  「どの要素がアンカーに選ばれるか」は仕様が実装に任せている部分で、このデモは広告がアンカーに選ばれることに頼っている。
  別の環境で「広告を伸ばしても `auto` で段落が動かなかった（動いたのは記事全体を `none` にした枠だけ）」という報告があったが、
  このブラウザ（Browser pane）では再現しなかった。画面に UA を出しているので、結果と一緒に控えること。
  広告の上端を画面の上端に合わせて「全部見えている最初の要素」にしたが、それでも差が出るかは環境次第で、確かめきれていない。
- **ad は「広告が最初に見える要素」になる位置までスクロールしないと差が出ない。**
  最初は広告より上の段落が先に見える位置で試したら、その段落がアンカーに選ばれて広告が伸びても位置が動かず、
  3 枠とも同じ結果（差なし）になった。広告の上端が画面の上端に来る位置（`scrollTop` を広告の `offsetTop` に合わせる）にしたら差が出た。
- manual は、読んでいるメッセージが枠の下端に寄りすぎないよう、`scrollTop = 300` にした（最初の 150 だと位置が下端近く（251px）で見切れた）。
- 上の数字はこのブラウザで測った値。`auto` の補正量や `scroll` イベントの回数は、ブラウザごとの実装で変わりうる。
- 「どの要素がアンカーに選ばれるか」の説明は、結果から推測したもので、仕様のアルゴリズムまで確かめたわけではない。
- どのバリアントも、スクロール位置が先頭（`scrollTop = 0`）だとアンカーは働かないので、少しスクロールしてから測っている。

## アクセシビリティの注意

- **新着が画面の外に隠れる（`push-down`）。** `auto` のままだと、先頭に足した新着 3 件のうち、見えたのは 0 件だった。
  新着があることを、見た目の位置だけに頼らず知らせる必要がある（「新着 3 件」のボタンを出す、`aria-live` で通知するなど。一般的な指針で、この Playground では試していない）。
- **`auto` は、読んでいる位置を守る。** `basic` では、上に 3 件足されても、見ていた項目は 61px のまま動かなかった（`scrollTop` が自動で +90 された）。
  逆に `none` にすると 151px へずれた。画面を拡大して読んでいる人などは、ずれると読んでいた場所を見失いやすいはず（確かめていない）。
- **自前の補正と二重にかけると、位置が飛ぶ（`manual`）。** 読んでいたメッセージが 168px 上へ飛び、読んでいた場所を見失う。`none` にするか、自前の補正をやめる。
- `auto` は、アニメーション中に `scrollTop` を書き換え続ける（`animation` で `scroll` イベントが 49 回）。動きに敏感な人への影響は、確かめていない。
- 未確認: スクリーンリーダーの読み上げ位置と、スクロール位置の補正との関係。
