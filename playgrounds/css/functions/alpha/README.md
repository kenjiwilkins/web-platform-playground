## 試したこと

- `alpha(from var(--c) / 0.5)` で、元の色の色味を保ったまま不透明度だけを 0.5 / 0.2 に差し替えた。
- `calc(alpha * 0.5)` のように、元の色の不透明度を `alpha` キーワードで参照して計算した。
  元が `0.8` なら結果は `0.4`（`getComputedStyle` で `rgba(102, 51, 153, 0.4)` を確認）。
- `50%` のようなパーセント指定も通り、`0.5` と同じ結果になった。

## ハマりどころ

- 構文は `alpha(from <color> / <alpha-value>)`。`from` と `/` が必須で、`alpha(0.5)` や `alpha(red / 0.5)` は `CSS.supports` が false になる。
- 未対応ブラウザでは宣言ごと無効になり、背景が指定されず透明のままになる（`detect` は `CSS.supports` で判定）。
- 元の色がすでに半透明のとき、`color-mix(in srgb, var(--c) 50%, transparent)` は**差し替えではなく掛け算**になる。
  元が `0.8` だと `0.4` になり、`alpha(from var(--c) / 0.5)` の `0.5` とは別物。
- `rgb(from var(--c) r g b / 0.5)` と見た目は同じだが、計算値の形が違う。
  `alpha()` は `rgba(102, 51, 153, 0.5)`（元の色空間のまま）、`rgb(from …)` は `color(srgb 0.4 0.2 0.6 / 0.5)` になる。

## 使いやすくなったところ

不透明度だけを変えたい場面で、これまでの書き方にあった手間が減る。

- 以前は `rgb(from var(--c) r g b / 0.5)` のようにチャンネルを全部書く必要があった。
  `alpha(from var(--c) / 0.5)` なら、意図（不透明度だけ変える）がそのまま読める。
- `color-mix(…, transparent)` の回避策は、元の不透明度と掛け算になるうえ、割合を計算し直す必要があった。
  `alpha()` は値をそのまま指定できる。
- 色が `oklch()` でも `hsl()` でも、色空間ごとのチャンネル名を意識せずに書ける。
- 設計トークンの 1 色（`--c`）から、ホバー用の薄い色や影の色を派生させやすい。
  色を直書きせずトークンだけで済ませる、というこのリポジトリの方針とも相性がよい。
