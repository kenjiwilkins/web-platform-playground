## 試したこと

- **構文は `progress(値, 開始, 終了)`（カンマ区切り）。** 最初に `progress(値 from 開始 to 終了)` と書いたが、これは別の関数（`media-progress()` など）の書き方で、
  Chrome 156 では `CSS.supports` が `false` だった。カンマ区切りにすると `true` になった。Safari 27.2 でも `from ... to ...` は未対応だった。
- Chrome 156 で `calc(progress(x, 0, 10) * 100px)` を `margin-left` に入れて読んだ結果:
  `x = -5` → `0px`、`0` → `0px`、`5` → `50px`、`10` → `100px`、`15` → `100px`。**範囲の外はクランプされ、0〜1 に収まる。**
- 単位付き（`progress(5px, 0px, 10px)`）も `50px` になった（比は単位なしの数値）。開始と終了を逆にした `progress(5, 10, 0)` は `50px`（比は 0.5）だった。
- スライダー（0〜200）の値を `--v` に入れ、`progress(var(--v, 50), 100, 200)` を幅の比に使うバーを置いた。

## ハマりどころ

- 書き方を間違えると、エラーにならず、宣言ごと無効になる（`CSS.supports` が `false`）。「ブラウザが未対応」と見分けがつきにくい。
- 返り値は `<number>` で、`%` や `px` の単位は付かない。幅に使うときは `calc(progress(...) * 100%)` のように掛ける。
- `width` は負の値を 0 に丸めるので、範囲外の動きを見るときは `margin-left` のように負の値を受け付けるプロパティを使う。
- `var()` を含む式は、`CSS.supports` では構文が間違っていても `true` になる。判定には、変数を含めない式を使う。

未確認: Safari や Firefox でカンマ区切りが動くか（Safari 27.2 では `from ... to ...` が未対応だったことのみ確認）。

## バリアント `battery`: バッテリー残量

1 つの値 `--level`（0〜100）から、幅・色・警告の濃さを `progress()` で導く。

- 幅: `calc(progress(var(--level), 0, 100) * 100%)`
- 色: `color-mix(in oklch, 赤 calc((1 - progress(var(--level), 15, 50)) * 100%), 緑)`
- 警告の不透明度: `calc(1 - progress(var(--level), 10, 25))`

Chrome 156 で、同じ CSS を別ページに注入して `--level` を変えながら計算値を読んだ（Playground 自体の描画は未確認）:

| 残量 | バーの幅（全体 240px） | 色             | 警告の不透明度 |
| ---- | ---------------------- | -------------- | -------------- |
| 100  | 240px                  | 緑             | 0              |
| 50   | 120px                  | 緑             | 0              |
| 30   | 72px                   | 黄に近い中間色 | 0              |
| 15   | 36px                   | 赤             | 0.67           |
| 10   | 24px                   | 赤             | 1              |

- 範囲の端でクランプされるので、`--level` が 100 を超えたり負になったりしても、色や不透明度は壊れない。
- `@property --level` を `<number>` で登録している。`style.setProperty('--level', n)` で値を変えるだけで、CSS 側が再計算される。

### アクセシビリティの注意

- バーは `role="meter"` と `aria-valuenow` / `aria-label` で値を持たせている。色の違いだけで残量を伝えないよう、数値も表示している。
- 未確認: VoiceOver での読み上げ、Tab 操作（スライダーと放電ボタン以外はフォーカスされない想定）、`prefers-reduced-motion` への配慮（放電中のバーは `setInterval` で更新しており、CSS のアニメーションは使っていない）。
